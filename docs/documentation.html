功能特性

VidiTranslate 提供端到端的视频翻译工作流，从 YouTube 链接直接输出带双语字幕的翻译视频。

📥

视频下载

输入 YouTube 链接，自动通过 yt-dlp 下载最佳质量视频。支持网络代理环境。

🎙️

语音识别 (STT)

支持 4 种引擎：OpenAI Whisper API、本地 Whisper API、本地 Whisper CLI、WhisperX。识别精确到句子级时间戳和说话人分离。

🗣️

说话人声纹标注

STT 后自动提取每位说话人的语音样本，用户标注性别/年龄后，TTS 自动匹配对应音色。

🌐

智能翻译

支持 OpenAI (GPT-4o)、DeepSeek、GLM 智谱三大 LLM 服务商，上下文感知翻译。

🔊

语音合成 (TTS)

Edge TTS（免费）、OpenAI TTS、IndexTTS（语音克隆）。按说话人性别自动选择音色，支持自然/严格两种时间同步模式。

🎬

视频合成

FFmpeg 自动替换音轨 + 烧录 ASS 双语字幕，输出最终 MP4 文件。

💾

断点缓存

每个处理阶段的结果缓存到本地，基于内容指纹校验。中断后重新运行自动跳过已完成步骤。

📝

仅字幕模式

保留原始音频，只生成双语字幕并烧录到视频。适合不需要配音的场景。

处理流程

完整翻译模式包含 6 个步骤，仅字幕模式跳过语音合成步骤（5 步）。

安装部署

环境要求

依赖版本说明
Node.js≥ 18运行时环境
npm≥ 9包管理器
yt-dlp最新视频下载工具，需在 PATH 中
Python 3.8+可选本地 Whisper CLI / WhisperX 模式需要
edge-tts (pip)可选Edge TTS 引擎，需在 PATH 中

安装步骤

# 1. 克隆仓库
git clone <repo-url>
cd video-translator

# 2. 安装 Node.js 依赖
npm install

# 3. 安装外部工具（macOS 示例）
brew install yt-dlp           # 视频下载
pip install edge-tts          # Edge TTS 语音合成（免费）

# 4. 可选：安装 WhisperX（推荐，支持说话人分离）
pip install whisperx          # 需要 Python 3.8+ 和 PyTorch

开发运行

# 启动开发模式（支持 HMR 热重载）
npm run dev

# 类型检查
npm run typecheck

# 生产构建
npm run build

💡 提示：FFmpeg 和 FFprobe 已内置在 npm 依赖中（ffmpeg-static + ffprobe-static），无需额外安装。

使用说明

基本工作流

  1. 配置 — 首次使用在 Settings 中配置 API Key、输出目录等
  2. 输入 — 在首页粘贴 YouTube 视频链接
  3. 选择模式 — 选择「语音翻译」或「仅字幕」模式
  4. 开始 — 点击开始按钮，进入自动处理流程
  5. 标注说话人 — 语音识别完成后，系统会暂停并展示每位说话人的音频样本，选择其性别/年龄（仅语音翻译模式）
  6. 等待完成 — 翻译和合成过程自动进行，进度条实时展示
  7. 查看结果 — 完成后在视频库中查看和打开翻译后的视频

说话人标注

当使用支持说话人分离的 STT 引擎（如 WhisperX）时，系统会在语音识别完成后暂停，展示每位说话人的音频样本供试听。用户为每位说话人选择一个音色类别：

  • 成年男性 — Edge: 云希/云健/云扬 | OpenAI: echo/onyx
  • 成年女性 — Edge: 晓晓/晓伊/晓珍 | OpenAI: nova/shimmer
  • 少年男性 — Edge: 云希 | OpenAI: fable/alloy
  • 少年女性 — Edge: 晓晓 | OpenAI: alloy/fable

IndexTTS 模式下，系统直接使用该说话人的音频样本作为克隆参考，无需选择预设音色。

缓存机制

每个视频的处理结果缓存在 {outputDir}/.tmp/{video-hash}/ 目录中：

  • audio.wav — 提取的音频文件
  • transcript.json — STT 结果（含指纹校验）
  • translated_segments.json — 翻译结果
  • tts.json — TTS 输出路径
  • speaker-profiles.json — 说话人标注缓存
  • speaker-samples/ — 说话人音频样本 (.wav)

修改配置后相关缓存会自动失效（基于内容指纹变更检测）。

数据契约

各 Pipeline 节点之间通过 TypeScript 接口定义数据契约。以下是核心数据结构规范：

TranscriptSegment（STT 输出）

字段类型约束
startnumber秒(float)，精度 ≥ 10ms，≥ 0
endnumber秒(float)，> start，允许跨 speaker 重叠
textstring完整句子（含标点），trim 后非空
speakerstring任意非空字符串，同一说话人全局一致
confidencenumber?可选，范围 [0, 1]

TranslatedSegment（翻译输出）

字段类型说明
startnumber保持原始 STT 时间戳不变
endnumber保持原始 STT 时间戳不变
sourceTextstring原文（== 原始 segment.text）
targetTextstring译文
speakerstring透传自 TranscriptSegment

SpeakerProfile（说话人档案）

字段类型说明
idstring说话人 ID（同 segment.speaker）
genderSpeakerGender'adult-male' | 'adult-female' | 'child-male' | 'child-female'
samplePathstring音频样本文件路径（wav）
sampleDataUrlstring?base64 data URL（用于前端播放）

SynthesisResult（TTS 输出）

字段类型说明
audioPathstring合成音频文件路径
segmentTimingsarray每段实际时间，长度 == segments.length
segmentTimings[].startnumber最终音频中的起始时间（秒）
segmentTimings[].endnumber最终音频中的结束时间（秒）
segmentTimings[].actualDurationnumberTTS 实际生成的音频时长（秒）
